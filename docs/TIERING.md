# Tiered pipeline: a browser only where it pays

Generated by `techdetect evaluate tiering` from the saved raw data (`data/raw/`), the rules and `data/ground_truth.json`. Do not edit by hand.

- **Run:** tool `0.1.0+38c0b696d36f`, rules `webappanalyzer@9e52f10a9533+custom:6998cfbdf29a+corrections:1e947e08fdbf`, confidence threshold 1 (as `techdetect detect`).
- **Cheap tier** (every domain, no browser): static fetch, certificate, robots.txt, DNS and URLs inside inline scripts. The script files downloaded over plain HTTP are left out: most of what they add is a mention inside a bundle (`docs/ABLATION.md`).
- **Policy** (decided from the cheap tier's result only): send a domain to the browser if the cheap tier found a shop (category Ecommerce: the client's market), a tag manager (it injects trackers only a running page shows), or a plain fetch blocked by a bot check or a TLS/connection error (a browser may get past it; a site that is down is not sent). That last rule was read off these same 200 domains, so it is tuned to them.
- **Precision** uses the existing labels of the 20 labelled domains; detections made by the inline-URL approach there may have no verdict yet (column Unlabelled), so precision does not cover them (see `docs/ABLATION.md` for how those approaches were checked).
- **Recall** is measured on the 10 blind domains, and 9 rules were written for misses on those same domains, so recall here is fitted to that set; 66% (75/113) is the last independent figure.
- **Cost** is the average wall time per domain from the collect run log; the tiered row pays the browser only for the domains it sends. CPU and memory per browser were not measured.
