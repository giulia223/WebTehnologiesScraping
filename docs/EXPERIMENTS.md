# Experiments

Every change that affects the numbers gets a row in the runs table below, naming the hypothesis it tests.

## Hypotheses

These claims come from research and from other projects. They are **not verified**. Each one is confirmed or refuted by a run below, and the outcome is reported with numbers.

"webappanalyzer" is the open technology-fingerprint database (a maintained continuation of Wappalyzer's last open rule set) that this tool matches against.

| ID | Claim (unverified) | Tested by | Result |
|---|---|---|---|
| H1 | A browser finds ~30-40% more technologies than static HTML | Comparing detections from the static fetch vs the rendered browser page | Run 5: more than claimed. Unique core 216 (static fetch, certificate, robots.txt) -> 332 with the browser: +116 names, +54%. Recall on the blind set 36% (41/113) -> 59% (67/113); precision 99% in both rows. |
| H2 | webappanalyzer rules alone give ~300-430 unique technologies on this list | The first full detection run | Run 1: 347 core, 414 extended: in range. First measured precision (Run 2b, 344 core): 90% (299/334) on 20 labelled domains; recall 65% (74/113). |
| H3 | The browser tier costs ~8x the static tier per domain | Timing the static and browser collectors, then the throughput benchmark | Run 5, wall time only: less than claimed. Browser step 10.12 s vs static fetch 4.08 s per domain (2.5x); static row 5.58 s vs + browser 15.70 s (2.8x). CPU and memory per browser were not measured (the benchmark was cut), and they are the larger cost at scale, so the claim is not settled. |
| H4 | Subpages mainly add payment / chat / forms / reviews technologies | Crawling a few subpages per site and comparing | - |
| H5 | DNS reveals SaaS (email, CRM, support) invisible in HTML | Adding DNS records as a signal | - |
| H6 | Each coverage expansion lowers precision unless its evidence tier is accounted for | Measuring precision after each expansion | - |
| H7 | Analytics/marketing tools on Shopify stores are often visible only in network traffic (web pixels), not in HTML | Comparing HTML vs network-request evidence on Shopify stores | Too few Shopify stores to test (2 of 154 working sites). On both, Google Analytics and Google Tag Manager were seen only by the browser, and Facebook Pixel on one. On all sites, 42% (53/126) of the detections of the 7 most common trackers (Google Analytics 19/50, Google Tag Manager 18/55, Facebook Pixel 5/9, Microsoft Clarity 4/4, Matomo 4/4, LinkedIn Insight Tag 2/3, Hotjar 1/1) were seen only by the browser (`leads.csv`, column `only_seen_by_browser`). "Only by the browser" means every piece of evidence came from the rendered page or the browser's requests, cookies and variables; web-pixel sandboxes were not separated. |
| H8 | An honest robot User-Agent gets noticeably more bot-check pages / fewer technologies than a Chrome User-Agent | Re-running the static fetch with a Chrome User-Agent | - |

- **Unique core**: distinct technology names (no versions) with at least one *observed* (seen working) or *declared* (the site states it) piece of evidence from the website itself.
