# Ablation: what each collection step adds

Generated by `techdetect evaluate ablation` from the saved raw data (`data/raw/`), the rules and `data/ground_truth.json`. Do not edit by hand.

- **Run:** tool `0.1.0+f19dd742a014`, rules `webappanalyzer@9e52f10a9533+custom:19e0e003c61d+corrections:d70ee8a77bec`, confidence threshold 0.
- **How:** detection is re-run once per row, each time allowing one more collection step. It is re-run, not filtered: a technology implied by one found only in the browser disappears with it. **static+** is the static row plus the URLs written inside the page's inline scripts (no extra request, so no extra cost); the browser rows do not read inline URLs.
- **Same domains in every row:** a domain's status and redirect always come from both fetches, so only the evidence differs. A static-only tool would also lose the pages only the browser could read: here the static fetch read 144 and the browser 151 of the 154 counted working sites.
- **Precision and recall** reuse the existing labels (20 labelled domains). Detections without a verdict (possible when a smaller set of evidence changes what is excluded or implied) are left out and counted in the table.
- **Cost** is the average wall time per domain of the steps a row uses, from the collect run log (latest run of each step). CPU and memory per browser, the real cost at scale, were not measured.
